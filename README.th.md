PUI89 เป็นโครงการ Industrial AI ที่พัฒนาอย่างอิสระและให้ความสำคัญกับซอฟต์แวร์เป็นหลัก มุ่งสำรวจการพัฒนาซอฟต์แวร์ AI ที่นำกลับมาใช้ซ้ำได้ ระบบอัจฉริยะ แนวคิดหุ่นยนต์ และการเชื่อมต่อซอฟต์แวร์กับฮาร์ดแวร์ ครอบคลุมด้านเกษตรกรรม การตรวจสอบ การช่วยเหลือ และการเดินทางอัจฉริยะ

PUI89 ไม่ยึดติดกับฮาร์ดแวร์ผู้ผลิตรายใด โดยมุ่งศึกษาการทำงานของ AI ให้มีประสิทธิภาพและความน่าเชื่อถือบน CPU, GPU, NPU, MCU, เซนเซอร์ ระบบฝังตัว และแพลตฟอร์ม Edge Computing ทั้งนี้ PUI89 ไม่ได้ดำเนินธุรกิจผลิตชิปเซมิคอนดักเตอร์

## ความร่วมมือทางเทคโนโลยี

PUI89 ยินดีรับการติดต่อเพื่อหารือทางเทคนิคและข้อเสนอการประเมินเทคโนโลยีจากสตาร์ทอัพด้านฮาร์ดแวร์ AI และหุ่นยนต์ ผู้ผลิตฮาร์ดแวร์ บริษัทเทคโนโลยี มหาวิทยาลัย สถาบันวิจัยอิสระ นักพัฒนา AI ทีมวิศวกรรม และชุมชนโอเพนซอร์ส

### นำฮาร์ดแวร์ของคุณมาร่วมประเมินทางเทคนิคกับ PUI89

บริษัท สตาร์ทอัพ และผู้พัฒนาเทคโนโลยีสามารถเสนอการนำฮาร์ดแวร์ที่เข้ากันได้ของตนเองมาหารือเพื่อประเมินทางเทคนิคร่วมกับ PUI89 ได้ หัวข้อที่อาจประเมิน ได้แก่ CPU, GPU, NPU, MCU และ AI Accelerator; Edge AI; การเลือกและปรับขนาดโมเดล; Quantisation; เซนเซอร์หลายรูปแบบ; ส่วนประกอบหุ่นยนต์; ความเข้ากันได้ระหว่างฮาร์ดแวร์กับซอฟต์แวร์; ประสิทธิภาพการใช้ทรัพยากร; ความน่าเชื่อถือ; การจัดการข้อขัดข้อง; และการทดสอบที่ทำซ้ำได้

การประเมินแต่ละครั้งขึ้นอยู่กับความเหมาะสมทางเทคนิค ขีดความสามารถที่มี ความปลอดภัย และเงื่อนไขที่ทั้งสองฝ่ายตกลงเป็นลายลักษณ์อักษร PUI89 ไม่ได้รับประกันว่าจะสามารถรับหรือทดสอบอุปกรณ์ทุกชิ้นที่มีผู้เสนอมา

## สถาปัตยกรรมแพลตฟอร์ม: Shared AI Core

**Shared AI Core คือแพลตฟอร์มวิศวกรรมที่ใช้ร่วมกันระหว่างโครงการของ PUI89 ไม่ใช่ผลิตภัณฑ์แยกต่างหาก** มีเป้าหมายเพื่อสร้างส่วนเชื่อมต่อและแนวปฏิบัติด้านความปลอดภัยและหลักฐานที่สามารถนำกลับมาใช้ซ้ำในผลิตภัณฑ์แต่ละรายการได้ตามระดับความพร้อม

สถาปัตยกรรมกำหนดสัญญาข้อมูลร่วมกัน 4 ส่วน ได้แก่

- **Observation** — ข้อมูลนำเข้าที่ระบุแหล่งที่มา เวลา รูปแบบข้อมูล คุณภาพ และที่มาของข้อมูลได้
- **WorldState** — การตีความข้อมูลที่สังเกตได้ตามช่วงเวลา โดยแสดงความไม่แน่นอนและข้อมูลที่ขาดหาย
- **ActionProposal** — ข้อเสนอแนะที่มีขอบเขตชัดเจนและสามารถตรวจสอบได้ก่อนดำเนินการที่มีผลสำคัญ
- **FailureReport** — บันทึกอย่างเป็นโครงสร้างเกี่ยวกับข้อขัดข้อง การทำงานที่ลดระดับลง ข้อมูลนำเข้าที่ถูกปฏิเสธ และหลักฐานการกู้คืนระบบ

แนวทางวิศวกรรมร่วมประกอบด้วยการตรวจสอบย้อนกลับของหลักฐาน การให้เหตุผลที่คำนึงถึงความไม่แน่นอน การงดให้คำตอบเมื่อหลักฐานไม่เพียงพอ การเข้าสู่สถานะพักอย่างปลอดภัย การทดสอบจำลองความขัดข้อง การทดสอบที่ทำซ้ำได้ และการอนุมัติโดยมนุษย์สำหรับการดำเนินการที่สำคัญ ทั้งหมดนี้เป็นแนวทางการออกแบบและพัฒนา โดยแต่ละ repository จะระบุสิ่งที่พัฒนาและทดสอบจริง

## ทิศทางแพลตฟอร์ม PUI89 — Industrial AI ที่เน้นซอฟต์แวร์เป็นหลัก

ทิศทางระยะยาวของ PUI89 คือการพัฒนา **แพลตฟอร์ม Industrial AI** จากซอฟต์แวร์และความสามารถทางวิศวกรรมที่นำกลับมาใช้ซ้ำได้ เป้าหมายคือทำให้ระบบ AI ทำงานได้อย่างน่าเชื่อถือภายใต้ข้อจำกัดของผลิตภัณฑ์จริง ไม่ใช่การผลิตชิปเซมิคอนดักเตอร์ และไม่ใช่การกล่าวอ้างว่าความสามารถที่เสนอไว้ทั้งหมดได้รับการพัฒนาแล้ว

หัวข้อวิศวกรรมร่วมประกอบด้วย

- **Perception & Task Intelligence (PTI):** กระบวนการ observe → perceive → assess → decide → respond ที่ตรวจสอบย้อนกลับได้ พร้อมแสดงความไม่แน่นอน การงดให้คำตอบเมื่อหลักฐานไม่เพียงพอ และการทบทวนโดยมนุษย์
- **General Multimodal Intelligence:** การผสานข้อมูลภาพ เสียง ข้อความ มิติพื้นที่ แผนที่ และอนุกรมเวลา โดยรักษาข้อมูลแหล่งที่มา เวลา คุณภาพ และข้อจำกัดเฉพาะของแต่ละรูปแบบข้อมูล
- **Heterogeneous Compute Intelligence:** การวิจัยการจัดสรรงานให้เหมาะสมกับ CPU, GPU, NPU และ MCU รวมถึงข้อจำกัดด้านหน่วยความจำ เซนเซอร์ และพลังงาน ตลอดจนการประเมินขนาดโมเดล quantisation การจัดตารางงาน edge inference และระบบสำรองที่ปลอดภัย
- **Simulation & Digital Twin Engineering:** การจำลองกระบวนการ เส้นทาง และหุ่นยนต์เป็นลำดับขั้น เพื่อทดสอบสมมติฐานก่อนสร้างต้นแบบภายใต้การควบคุม ทั้งนี้ผลการจำลองไม่ใช่การตรวจสอบสมรรถนะทางกายภาพ
- **Safety, Security & Recovery:** แยกข้อเสนอจาก AI ออกจากระบบควบคุมความปลอดภัยอิสระ ใช้สิทธิ์เท่าที่จำเป็น บันทึกการเปลี่ยนแปลง รายงานข้อขัดข้อง เก็บหลักฐานการกู้คืน และกำหนดให้มนุษย์อนุมัติการดำเนินการที่มีผลสำคัญ
- **Hardware & Materials Engineering:** บันทึกข้อมูลระบุตัวตนของชิ้นส่วน ความเข้ากันได้ ผู้ผลิต หลักฐานแหล่งกำเนิด ผู้จำหน่าย ต้นทุนตามวันที่ และระยะเวลาจัดส่ง ก่อนตัดสินใจจัดซื้อ
- **Open-source-first Technology Governance:** ตรวจสอบที่มา ใบอนุญาต ความปลอดภัย ความเป็นส่วนตัว ความต้องการทรัพยากร และการบำรุงรักษา ก่อนนำโค้ด โมเดล หรือชุดข้อมูลภายนอกมาใช้

หัวข้อเหล่านี้เป็นแนวทางวิศวกรรมร่วม แต่ละผลิตภัณฑ์จะเลือกใช้เฉพาะความสามารถที่เกี่ยวข้องกับภารกิจของตน และจะกล่าวอ้างว่ามีการพัฒนาหรือตรวจสอบยืนยันแล้วต่อเมื่อมีหลักฐานจาก repository และการทดสอบที่ทำซ้ำได้รองรับ

## แผนงานวิศวกรรม

การพัฒนามุ่งดำเนินไปตามด่านการตรวจสอบหลักฐาน แทนการระบุเปอร์เซ็นต์ความสำเร็จที่ไม่มีหลักฐานรองรับ

1. **พื้นฐานร่วม:** กำหนดและทดสอบสัญญาข้อมูล แหล่งที่มา ความไม่แน่นอน และการจัดการข้อขัดข้อง
2. **การประเมินซอฟต์แวร์:** สร้างการทดสอบที่ทำซ้ำได้ พร้อมบันทึกชุดข้อมูล ใบอนุญาต ตัวชี้วัด และข้อจำกัด
3. **การจำลองและการทดลองแบบควบคุม:** ประเมินสถานการณ์ กรณีขอบ และพฤติกรรมเมื่อเกิดข้อขัดข้อง พร้อมระบุผลการจำลองให้ชัดเจน
4. **การผสานฮาร์ดแวร์:** ดำเนินการเมื่อมีทรัพยากร มาตรการความปลอดภัย และแผนการทดสอบพร้อมแล้วเท่านั้น
5. **การตรวจสอบภาคสนาม:** รายงานสมรรถนะในโลกจริงหลังจากมีการทดสอบที่จัดทำเอกสารและทำซ้ำได้ รวมถึงพิจารณาข้อกำหนดด้านความปลอดภัยและกฎระเบียบก่อนนำไปใช้งาน

การระบุรายการในแผนงานไม่ได้หมายความว่าผ่านด่านดังกล่าวแล้ว สถานะและหลักฐานปัจจุบันต้องอ้างอิงจาก repository และหน้าโครงการที่เกี่ยวข้อง

## หลักฐานและสถานะการพัฒนา

PUI89 แยกสถานะการพัฒนาให้ชัดเจนดังนี้

- **Implemented software — ซอฟต์แวร์ที่พัฒนาแล้ว:** มีโค้ดอยู่ใน repository
- **Tests run — การทดสอบที่ดำเนินการแล้ว:** มีการรันทดสอบจริง และควรบันทึกผลกับขอบเขตการทดสอบ
- **Synthetic or simulated evaluation — การประเมินด้วยข้อมูลสังเคราะห์หรือการจำลอง:** ผลลัพธ์จำกัดอยู่ภายใต้เงื่อนไขข้อมูลสังเคราะห์หรือสถานการณ์จำลองที่ระบุ
- **Proposed design — แนวคิดที่เสนอ:** แนวคิด สถาปัตยกรรม หรือเป้าหมายทางวิศวกรรมที่ยังไม่ได้สาธิตให้เห็นจริง
- **Validated physical performance — สมรรถนะทางกายภาพที่ตรวจสอบยืนยันแล้ว:** มีหลักฐานจากการทดสอบบนฮาร์ดแวร์จริงภายใต้เงื่อนไขที่ระบุ

การทดสอบซอฟต์แวร์ผ่านไม่ได้ยืนยันความแม่นยำของโมเดลในโลกจริง ความสามารถของหุ่นยนต์ ความปลอดภัยในการปฏิบัติงาน การรับรองมาตรฐาน หรือความพร้อมเชิงพาณิชย์ การกล่าวอ้างสมรรถนะทางกายภาพต้องมีหลักฐานการทดสอบที่เกี่ยวข้องรองรับ และแนวคิดหรือเป้าหมายทางวิศวกรรมต้องระบุสถานะให้ชัดเจน

พอร์ตโฟลิโอใช้แนวทางที่ให้ความสำคัญกับโอเพนซอร์สและการใช้ทรัพยากรอย่างรอบคอบ โค้ด โมเดล ชุดข้อมูล และ checkpoint จากภายนอกต้องผ่านการตรวจสอบใบอนุญาต ที่มา ความปลอดภัย และความต้องการทรัพยากรฮาร์ดแวร์แยกต่างหากก่อนนำมาใช้

## ความร่วมมือและการมีส่วนร่วม

PUI89 ยินดีรับความร่วมมือด้านการวิจัยและวิศวกรรมในสาขา AI ประยุกต์ คอมพิวเตอร์วิทัศน์ ระบบหลายรูปแบบข้อมูล หุ่นยนต์ การจำลอง วิศวกรรมความปลอดภัย และการประเมินผลที่อาศัยหลักฐาน

แนวทางการมีส่วนร่วม:

1. อ่าน README และประเด็นที่เปิดอยู่ใน repository ของโครงการที่เกี่ยวข้อง
2. เปิด issue เพื่อหารือข้อเสนอการเปลี่ยนแปลงก่อนเริ่มงานขนาดใหญ่
3. ส่ง pull request ที่มีขอบเขตชัดเจน พร้อมเหตุผล วิธีทดสอบ และหลักฐาน
4. ระบุข้อจำกัด ที่มาของข้อมูลหรือโมเดล และแยกให้ชัดว่าผลลัพธ์มาจากข้อมูลจริง ข้อมูลสังเคราะห์ หรือการจำลอง

การมีส่วนร่วมทุกประเภทควรมีเอกสารประกอบ ตรวจสอบได้ และทดสอบได้ ห้ามสื่อว่าต้นแบบพร้อมใช้งานภาคสนามหรือได้รับการรับรองความปลอดภัย หากไม่มีหลักฐานรองรับ
